# 学习框架笔记（learning-framework-notes）

> 一个把「零散资料」变成「可自学教材」的 Agent Skill。
> 给素材，就按统一骨架成书；不给素材，就产出可填写的骨架。

## 这是什么

`learning-framework-notes` 是一个面向 Claude Code / ZCode 等支持 `SKILL.md` 的 Agent 的技能包。它把一套固定的自学教材结构（宏观导航 + 微观套路）固化成模板，让 Agent 帮你把书、讲义、题库、笔记、论文重组成**能一刷通读、二刷速查、考前定位**的教材。

适合这些场景：

- 手头有 PDF / 讲义 / 多份笔记，但内容散、不成体系，想要一份能按顺序学下去的自学材料
- 复习时只想快速查「这类题怎么识别、怎么下手」，需要一张套路速查表
- 想要一个空教材骨架，自己往里填内容
- 想把同一领域的多份资料合并成一本教材，并保留每道题的来源与时间

## 两种模式

| 模式 | 触发条件 | 产出 |
|---|---|---|
| **成书模式** | 用户提供了素材（PDF / Markdown / 书 / 题库 / 多份文件），且没明说「只要骨架」 | 骨架 + 完整章节内容 |
| **建骨架模式** | 没提供素材，或用户明说「只要形式 / 只要骨架」 | 形式 + `{占位符}`，不编造学科内容 |

两种模式共用同一套模板与编写规范，区别只在「填不填内容」。

## 核心设计

### 1. 宏观：全书骨架

一本书只做这几件事：

- **第 0 章**：阅读路径表、全书主线与依赖图、符号表、基础预备、自检问题总表
- **第 1 ~ N 章**：知识模块，每章套用同一份章模板
- **倒数第 2 章**：公式与方法速查总表（汇总各章套路与核心公式）
- **倒数第 1 章**：分支概念地图（共同基础 → 各分支 → 扩展条件）
- **附录 A**：反向索引（按来源 / 时间倒序，由题目元数据自动生成）
- **附录 B**：自检问题全集（答不清 → 回跳对应章）

### 2. 微观：章模板

每章固定 `X.0 ~ X.6` 七块：

| 块 | 内容 |
|---|---|
| X.0 章导读 | 前置基础、本章问题、核心内容、后续衔接 |
| X.1 学习目标表 | 学完能做到什么、负担重时优先抓什么 |
| X.2 核心知识点 | 作用先说 → 定义/定理 → 显式推导 → 证明思路 |
| X.3 套路速查表 | 套路名、识别信号、一句话方法、关键易错 |
| X.4 套路详解 | 每个套路固定七步 |
| X.5 习题库 | 原题 + `[来源·时间]`，按基础/变式/综合/跨章分层 |
| X.6 章末复盘 | 本章在依赖图上的位置、跨章连接点、自检问题汇总 |

**套路七步**：何时使用 → 典型例题 → 思路推演 → 形式化解答 → 套路提炼 → 易错点 → 关联编号。

### 3. 规矩：编写规范

五条硬规则约束成书质量：

1. 自检问题一律用能力动词（「能否用 A 做 B」），禁止「是否理解 X」式提问
2. 易错点一律写成「反例 + 为什么错」，禁止「注意 XX」式空话
3. 推导显式展开，不跳关键步骤
4. 首次出现给完整推导，复用写「沿用 {编号}」作为二刷索引
5. 一刷读者应能无视导航元素线性读通；二刷时导航元素才发力

此外还定义了统一的 ID 体系（`ch{X}-pat-{n}` / `ch{X}-ex-{nnn}` / `ch{X}-sec-{n}`）和三张自动索引网：依赖网、套路网、时间网。

### 4. 底线：内容溯源

成书模式下，内容必须溯源到用户素材：

- 改写表述可以（这正是重构的价值）；编造事实、例题、公式、数据、出处不行
- 素材没覆盖的块写 `{素材未覆盖：需要什么}`，不硬编，收尾时汇总成清单
- 素材自带的题号、年份、来源原样保留；没有的按 `ch{X}-ex-{nnn}` 重新编号

## 目录结构

```text
learning-framework-notes/
├── SKILL.md                 # 技能入口：模式判断、流程、硬约束
├── references/
│   └── 成书流程.md           # 成书模式的执行手册（读素材 → 规划 → 逐章 → 收尾）
└── assets/
    ├── 全书骨架.md           # 全书宏观结构模板
    ├── 章模板.md             # 每章 X.0 ~ X.6 模板
    └── 编写规范.md           # 五条硬规则、ID 规范、索引网、推进路线
```

## 安装

### Claude Code

```bash
git clone https://github.com/qiuzz1414-cpu/learning-framework-notes.git \
  ~/.claude/skills/learning-framework-notes
```

### ZCode / 其他兼容 Agent

放到 Agent 的 skills 目录即可（常见为 `~/.agents/skills/` 或 `~/.zcode/skills/`）：

```bash
git clone https://github.com/qiuzz1414-cpu/learning-framework-notes.git \
  ~/.agents/skills/learning-framework-notes
```

也可以从已有目录做软链接：

```bash
ln -s /path/to/learning-framework-notes ~/.agents/skills/learning-framework-notes
```

安装后保持 `SKILL.md`、`references/`、`assets/` 的相对位置不变——`SKILL.md` 里用相对路径引用后两者。

## 使用

直接用自然语言触发，或显式调用 `/learning-framework-notes`。

**成书模式**：

```text
把 ~/Downloads/信号与系统讲义.pdf 整理成教材
```

```text
用学习框架笔记把这几个文件合成一本教材：a.pdf、b.md、c.pdf
```

**建骨架模式**：

```text
给我一个《概率论》教材骨架，只要形式，不要内容
```

**其他变体**：

```text
只要在对话里看看全书骨架和章模板长什么样
```

```text
只把素材里第 3 章的内容按章模板成文
```

### 成书模式会先确认四件事

主题名称、素材位置、输出目录（默认 `{主题}-学习框架/`）、是否先出样章（默认**先出**）。

### 建骨架模式会先确认三件事

主题名称（可留 `{主题}`）、章模板份数、输出目录。

## 产出长什么样

```text
{主题}-学习框架/
├── 00-编写规范.md
├── 01-全书骨架.md          # 真实章名、依赖图、素材来源标注
├── 02-章模板.md
└── chapters/
    ├── ch1-{章名}.md
    ├── ch2-{章名}.md
    └── ...
```

每章内部按 `X.0 ~ X.6` 组织；每个套路带七步；每道题带来源与编号。收尾时会额外生成速查总表、分支概念地图和两个附录。

## 设计原则

- **样章先行**：先完整跑通一章交用户确认，再批量生产。最大的坑是全书骨架搭满、每章平均用力，规范没经过真实使用就定型。
- **文件分工固定**：全书骨架定宏观、章模板定每章、编写规范定填法，不随意增删模块。
- **成书不编造**：素材没有的，标出来，不猜。
- **为两种读法设计**：一刷线性读，二刷靠导航和索引定位。

## 适用素材

整本书 PDF、课程讲义、题库、多份零散笔记、论文，或一个空白主题。素材很大时会先读目录与抽样章节建全局地图，再逐章深读；一次读不完就分批处理，并把已确认的套路清单与元数据表记进 `01-全书骨架.md` 作为跨章一致性锚点。
